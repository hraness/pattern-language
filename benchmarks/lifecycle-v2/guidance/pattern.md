Use this small pattern language where its context applies. Equivalent implementations are welcome; pattern names are not evaluated.

1. Explicit lifecycle. Context: a component must distinguish ongoing work from a terminal outcome whose payload may be any value. Forces: concise representation competes with preserving every valid payload and every legal transition. Relationship: lifecycle state and payload occupy distinct roles. An explicit tag or flag records whether a terminal outcome exists; null, undefined, false, zero, and empty string are data, never the universal unset marker. Define legal transitions before attaching actions. Once a terminal cause is chosen, preserve it unless the contract explicitly permits replacement.

2. Owned obligations. Context: work may complete asynchronously or reenter its owner. Forces: prompt reaction competes with retaining responsibility for work already admitted. Relationship: an owner acquires an obligation before invoking reentrant work, normalizes arbitrary asynchronous completion through native promise assimilation, and releases exactly once. Closed admission and completed drainage are separate facts. Use this machinery only for operations that need it; a synchronous pure transformation needs no asynchronous bookkeeping.

3. Declared publication boundary. Context: internal progress can leave a result incomplete. Forces: incremental work competes with preserving the caller's visible invariants. Relationship: completion or state publication occurs only at the boundary permitted by validation and outstanding obligations. Keep construction separate from publication where the contract requires an all-or-nothing effect. A local state flag cannot make uncertain, irreversible external effects atomic. Reclaim listeners and other owned resources on every terminal path.

Sequence: identify identities and observable boundaries; enumerate states and legal transitions; assign obligations; attach effects to transitions; place publication and release. Consequences: additional state and bookkeeping, potentially indefinite drainage, and no guarantee beyond the specified effect boundary. Apply only the relationships required by the task. Return only the requested complete module.
