Consider the pattern Bounded Work Court. Context: ordered finite work shares scarce capacity. Forces: concurrency reduces idle capacity but unrestricted admission exhausts resources; completion order differs from identity; stopping new obligations competes with owning existing obligations. Resolution: establish one admission boundary, stable result addresses from snapshotted inputs, and one slot per admitted worker. A returning slot admits the next item only while the boundary remains open. Record the first terminal cause separately from outstanding obligations. Close admission immediately on failure; observe existing workers until they drain, then return ordered results or reject with that cause. Sequence: establish identity, bound admission, conserve slots, close, drain. Consequences: coordination state, linear result storage, and potentially unending drainage. Check synchronous throws and promise assimilation. The same completion accounting can accommodate a future termination cause. Countercontext: unrestricted streams or forced termination need another design. Use the relationship where helpful; any equivalent implementation is acceptable. Return only the requested module.
