Use this implementation checklist. Snapshot inputs and give every item a stable result address. Maintain a shared admission boundary and a count of outstanding obligations. Admit only while capacity is available, and give every admitted worker one slot until it settles. Store each successful result at its input address. Return a slot when its worker settles, then admit the next item if admission remains open. Record the first terminal cause separately from the outstanding count. On failure, close admission immediately; keep observing workers already admitted. Complete only after obligations drain, either returning ordered results or rejecting with the recorded cause. Check synchronous throws and promise assimilation. Keep the same completion accounting available for a future termination cause. The tradeoffs are coordination state, linear result storage, and waiting for workers that never settle. Apply these checks where useful; any behaviorally equivalent implementation is acceptable. Return only the final complete executable module requested by the contract.
